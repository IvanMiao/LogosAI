# 阅读工作台与常驻 Agent 实施设计

- 日期：2026-09-06
- 状态：2026-09-07 已实现 E1 阅读现场与导航；其余切片仍为目标设计
- 目标：围绕原文持续理解问题，在切换、回查和离开后恢复思考，并逐步接入用户级常驻 agent
- 优先级归属：[路线图](../roadmap.md)；本文定义切片内容和依赖，不另设一份执行队列
- 当前事实：[项目参考](../project.md)；现行行为：[旅程契约](workspace-journey-contract.md)
- 方法：依据当前代码静态审阅、产品讨论及公开设计分享；未使用 skill；E1 本地浏览器与自动化验证见[验收记录](reading-navigation-verification.md)，尚未完成真实云服务与用户验收

## 1. 产品目标与范围

核心体验：用户读 A 到一半，围绕某段追问，去 B 核对引用，再返回 A 接着阅读；隔天仍能找回问题、自己的笔记和已完成任务。

本次设计确立以下方向：

1. 原文、问题讨论和用户成果拥有稳定身份，布局变化不创建内容副本。
2. 阅读现场与内容分别保存；切换不隐式取消任务或改变任务上下文。
3. Explain、Translate、Vocab 是启动或推进讨论的快捷动作，保留一键入口。
4. 自动保存全部过程；笔记与收藏提供用户主动选择的重点视图。
5. 常驻 agent 有用户级连续性，每次执行具有明确范围；不等同于无限聊天记录或持续占据屏幕。
6. 界面强调当前阅读和问题，低频操作与运行细节按需展开。

本轮不直接实施：框架替换、完整知识图谱、多人协作、所有格式导入、通用 agent 平台、动态生成整个应用导航。现有 auth、BYOK、legacy analysis 和 history 导入继续兼容。

“开始阅读”与“生成精读”的默认布局、短查询的展开方式、讨论与收藏的具体入口仍需原型验证；不要把外部产品实践当成已验证的 LogosAI 用户需求。

## 2. 设计时现状与改动依据（2026-09-06）

| 现状与代码入口 | 影响 | 目标 |
| --- | --- | --- |
| `WorkspacePage` 按 document ID 重建 `ReaderWorkspace`，`useWorkspaceViewState` 保存局部视图状态 | 回访布局、详情与位置缺少统一恢复机制 | 按用户和阅读对象保存现场 |
| `ReaderWorkspace` 条件渲染 History、单栏、双栏 | 视图切换会卸载阅读子树；实际滚动与焦点影响待浏览器复现 | 内容身份稳定，卸载后也能可靠恢复 |
| `HistoryWorkspace` 的查询、筛选、选择由组件局部管理 | 退出后难以回到原查找过程 | 保存查询现场和返回目标 |
| `App` 没有具体 session 与成果路由 | 刷新、浏览器后退和直接定位缺少明确语义 | 稳定地址与导航记录 |
| `CurrentExplainPanel` 汇集多类输出并使用版本菜单 | 问题、输出类型与版本混杂 | 讨论、成果和修订分别表达 |
| `useArtifactTasks` 控制器在浏览器内 | 无法据此保证关页后继续工作 | 后续引入服务端持久任务 |
| 阅读快照包含文档、anchors、artifacts；已有 revision 与同步 journal | 可复用保存基础，但 revision 存在不代表已解决并发冲突 | 新对象使用明确的同步与兼容契约 |

以上保留设计时依据；E1 现行恢复与地址行为见旅程契约，不声明已完成生产验收。

## 3. 信息架构与交互契约

### 3.1 工作区结构

| 区域 | 职责 | 常见内容 |
| --- | --- | --- |
| 可收起导航 | 找到并切换工作对象 | 最近阅读、固定阅读、搜索；后续增加最近讨论与任务 |
| 主阅读区 | 持续阅读 | 原文，或明确展开的精读/长讨论 |
| 辅助区 | 处理当前问题 | 讨论、笔记、精读；同一时刻聚焦一种内容 |

不同时堆叠解释栏和 agent 聊天栏。辅助区展开时使用同一 discussion/artifact ID；收回不复制对话，也不丢失位置。窄屏采用底部面板和全屏详情，避免把桌面多栏直接纵向堆积。

首次进入无成果文档时比较“原文优先”与“明确选择生成精读”两条路径；已有现场优先恢复。布局由可用内容宽度决定，不能只判断整个窗口是否达到桌面断点。

### 3.2 连续阅读

- 打开、关闭帮助不主动移动原文；只有“定位原文”或明确打开引用才跳转。
- 展开和收回长解释、进入和退出 History，都恢复来源视图、滚动和焦点。
- 流式输出仅在用户已跟随末尾时继续跟随；向上滚动后停止跟随，显示“查看新内容”。
- 引用默认短预览并支持展开；长选区不把首个有效回答推到很远的位置。
- 精读通过标题目录与精确引用连接原文，不用滚动比例推断语义位置。
- 短词查询可就地展示，再进入连续讨论；关闭即恢复原句，结果仍按现有自动保存策略保留。

### 3.3 讨论与选区

- 一次讨论围绕一个明确问题，可包含多个有来源标识的引用。
- 首次 Explain/Translate/Vocab 可创建讨论并记录动作类型，不要求用户先写 prompt。
- 同一选区打开已有成果不重新调用 AI；显式追问追加消息，重新生成产生修订。
- 新选区发起动作默认创建新问题；用户可显式“加入当前讨论”用于比较。
- 仅浏览或选中另一段不改写已发送消息、当前运行或既有讨论的范围。
- 一个选区可以关联多个不同问题；“同一选区”不足以判断两个问题是同一次讨论。
- 首版问题标题使用用户问题或确定性片段标题，支持重命名；不为每次操作额外发起标题生成。

### 3.4 预览、打开与返回

| 动作 | 预期行为 |
| --- | --- |
| 预览 B 的引用 | 在 A 的当前讨论中查看短引用；保留 A 的主阅读现场 |
| 打开 B 阅读 | 保存 A 的现场，正式导航到 B 的指定位置，提供返回路径 |
| 从历史打开成果 | 恢复该成果及原文位置，不请求模型 |
| 从成果返回历史 | 恢复查询、筛选、选中条目与列表位置 |
| 浏览器后退 | 返回上一个明确导航目标；不逐条回退滚动、拖拽和输入 |
| 引用被删除或定位不唯一 | 展示保存的引用和不可定位原因，不静默跳到近似位置 |

预览浮层不递归创建无限弹层；更深引用进入同一个预览区域或正式导航。关闭后焦点回到触发引用的控件。

### 3.5 History 与回访

现有 History 保持兼容入口，逐步提供三个视图，不立即增加三个顶层页面：

- **笔记与收藏**：用户笔记、明确收藏的解释及整理成果；AI 内容与用户原文清晰区分。
- **讨论记录**：问题标题、简短内容摘要、原文位置、更新时间，展开后查看追问和成果。
- **任务活动**：后台任务的状态、结果与需要处理的事项，在持久任务上线时加入。

全部过程自动保存；收藏决定重点呈现，不决定内容是否存在。取消收藏不删除成果。不同动作类型不是彼此的旧版本；修订收在同一逻辑成果内部。旧成果必须可搜索、定位、删除和恢复，不要求用户先迁移整理。

搜索明确显示“本篇 / 全部阅读”。先实现本篇；跨文档检索上线后再提供全局范围。移动端使用列表→详情→返回列表，不把详情放在整份长列表下方。

### 3.6 Session 导航

- 界面优先使用“阅读”“文档”，避免与未来 agent 对话 session 混用。
- 阅读条目显示标题、最近位置及少量状态；不默认展开全部成果子树。
- 固定阅读与固定侧栏是两个概念；固定阅读顺序稳定，最近阅读按最近打开排序。
- 提供快速切换与返回上一阅读；归档与删除分开，归档内容仍能搜索和恢复。
- 后台任务更新不把 session 顶到最近打开列表首位，不切换当前文档。

## 4. 数据、路由与状态边界

以下是目标模型，字段名与 API 在相关切片启动时通过 ADR 定稿；不直接替换现行契约。

### 4.1 对象关系

| 对象 | 责任与关系 |
| --- | --- |
| Document / Reading session | 延续现有一篇文本及其阅读成果集合；近期不拆成多文档项目 |
| Anchor | 原文坐标与引用，沿用 UTF-16 offset；为引用补全文档身份及定位校验 |
| Discussion | 问题、可选主要 document ID、相关引用、消息与成果关联；后续允许跨文档 |
| Message | 用户或 AI 的一次发言、所用范围、关联运行；已发送范围不可被后续选区变化覆盖 |
| Artifact | 可打开的解释、精读、笔记等成果；保留现有 ID，新增可选讨论与修订关联 |
| Saved reference | 用户收藏关系，指向成果；收藏不复制正文 |
| Run | 一次执行及终态，关联用户、讨论、目标成果和执行时上下文 |
| Reader view snapshot | 当前设备的阅读、详情、历史与布局现场 |
| Memory entry（后期） | 用户级偏好或确认过的长期信息，带来源、范围、更新时间及管理状态 |

同一输出若同时作为消息和成果展示，使用显式引用及唯一内容所有者，避免两份正文独立更新。Run 状态与成果保存状态分开；“任务成功”不代表“云端同步完成”。

### 4.2 状态归属

| 位置 | 保存内容 | 约束 |
| --- | --- | --- |
| URL | 文档、成果或讨论的稳定目标，必要的明确导航位置 | 不包含私人引文、笔记或搜索全文；URL ID 不代替权限检查 |
| 设备本地 | 布局、栏宽、面板位置、History 查询现场、返回栈 | 按用户隔离；不让另一设备改写当前窗口 |
| 云端 | 内容、讨论、收藏、任务；后期可选同步最后阅读位置 | 复用身份隔离；新并发写入需版本条件和冲突策略 |
| 瞬时状态 | 未确认 DOM selection、菜单、拖拽过程 | 不持久化 DOM Range 或节点引用 |

建议路由：`/app/readings/:documentId`，成果可用 `?artifact=:artifactId`；跨文档讨论使用 `/app/discussions/:discussionId`。具体 query 组合只容许一个主目标，非法组合回退到有效对象。`/app` 兼容恢复最近阅读或显示导入入口；`/app/analysis` 继续兼容。

进入深链先完成身份和数据加载，再验证目标归属；无法访问时提供清晰的不可用状态，不能闪现其他用户的缓存内容。滚动更新使用本地快照，布局与过滤调整不产生大量 `pushState`。

### 4.3 现场恢复算法

1. 切换前捕获原文可见文本位置、视口内偏移，及当前成果 ID、成果内位置、History 现场。
2. 按用户、document ID 和快照版本保存；切换时立即保存，滚动时节流，卸载事件仅作为补充。
3. 返回时先解析有效内容与布局，再在字体和容器尺寸稳定后恢复位置。
4. 原文用 offset 与短引用校验定位；字体/宽度变化后重新测量。Markdown 成果可用标题/内容块标识与相对偏移。
5. 恢复时用户已经主动滚动则停止后续纠正，防止延迟跳回。
6. 目标删除、版本失效或定位歧义时回退到可解释的有效位置并给出轻提示。

不通过常驻全部文档 DOM 解决恢复问题。应允许卸载，只缓存有界的近期视图状态。首次页面加载与内部导航的焦点恢复分别处理，避免自动抢走输入焦点。

### 4.4 内容保存与并发

- 笔记保存失败必须可见并保留草稿；切换文档不清空失败草稿。
- localStorage 无法写入时维持当前内存内容并提示恢复限制，不声称已经保存。
- Discussion/Message 宜采用追加与明确修改操作；不要把跨文档讨论塞进某个文档的整包替换快照。
- 新 endpoint 保持增量兼容；用户身份从 Worker 会话获取，后端继续经 gateway 调用。
- 服务端 agent 与浏览器可能同时写入成果；引入此能力前必须定义条件写入、幂等与冲突恢复，不能继续依赖无条件最后写入覆盖。
- 删除文档后，文档内成果按既有语义处理；跨文档讨论保留但相关引用标记不可用，不静默删除用户其他讨论。最终删除语义在迁移 ADR 中明确。

## 5. 可独立交付的实施切片

依赖：E0→E1→E2→E3→E4。E5 在 E1 后可独立开展，但最终布局跟随 E2/E3；E6 依赖已验证的讨论价值；E7 依赖 E6 和明确后台工作需求。路线图 N1/N2/N3 的可靠性与质量工作不被本设计跳过。

| 切片 | 实施内容与主要入口 | 依赖与退出条件 |
| --- | --- | --- |
| E0 基线与原型 | 用现有 `WorkspacePage`/旅程测试建立长文、重复选区、多成果 fixture；制作原文优先和精读优先的可操作原型 | 记录桌面/窄屏的切换、查找、返回基线；确认首个入口方案或保留明确待决项 |
| E1 阅读现场与地址 | `App`、`useWorkspaceViewState`、`ReaderWorkspace`、`ReadingSurface`、`HistoryWorkspace`；增加路由解析、按用户隔离的现场存储 | A→B→A、刷新、设置页返回、History 返回恢复通过；无新云端 schema 依赖 |
| E2 问题讨论与追问 | 增加 Discussion/Message；调整 `CurrentExplainPanel`、任务编排、client API、Worker 存储及 FastAPI 上下文输入 | N1 可靠终态先通过；三轮追问范围正确，切换选区不改变正在运行的问题；新数据真实恢复通过 |
| E3 成果与历史组织 | `HistoryWorkspace`、artifact selectors/schema；笔记与收藏、讨论摘要、修订入口 | E2；旧成果全部可访问，收藏取消不删除，过滤和返回现场保持，用户笔记不被 AI 覆盖 |
| E4 引用预览与跨阅读 | 统一引用组件、全局搜索与讨论范围；跨文档讨论使用独立生命周期 | E1/E2/E3；A→预览B→打开B→返回A通过，引用权限与删除路径通过 |
| E5 辅助区与视觉收敛 | 统一短查询、侧栏、全屏展开；`ReaderToolbar`、split layout、阅读导航与样式 | 同一讨论无副本；中等宽度不溢出；键盘和窄屏可完成同一旅程；默认布局有观察依据 |
| E6 用户级 agent 与记忆 | 在既有讨论能力上增加全局入口、可检查的上下文、偏好与长期记忆管理 | 单篇与跨篇讨论已有价值证据；限定记忆类型，支持修改/遗忘；无后台持续执行承诺 |
| E7 服务端持久任务 | 持久运行、状态订阅、取消、重连、幂等写入；任务活动视图 | Durable Jobs gate；关页后仍可完成，重连不重复成果，并发笔记不被覆盖；运行平台通过 ADR 决策 |

每个切片按数据/行为/展示的最小闭环拆成原子提交；不将全部 UI 改动、数据库迁移和 agent runtime 合成一个 PR。E2 的首版仅单篇讨论，E4 才扩展多篇范围。

## 6. 常驻 Agent 的具体边界

### 6.1 上下文与记忆

- 当前问题、明确选择的引文和相关前后文是默认上下文；检索扩大范围时显示来源。
- “只依据本篇”“不涉及后文”必须改变检索和 prompt 输入，并有对应评估样本。
- 文本中的主张、用户自己的观点、解释偏好分别存储和呈现，不合并成无来源总结。
- 长期记忆首版只支持显式保存的偏好和用户确认的信息；自动推断与主动建议后续单独验证。
- 用户可查看、修改、删除记忆；删除后不再检索使用，重建索引与缓存失效纳入验收。删除记忆不自动删除原始讨论，界面解释两者关系。
- 上下文摘要与来源可展开；不把内部推理过程或逐工具刷新当成透明度目标。

### 6.2 后台任务

UI 最少区分等待执行、执行中、需要处理、已完成、失败、已取消；与现有 artifact status 的映射在 API ADR 中确定，不直接扩大既有枚举。

每个任务记录目标、执行时上下文、当前阶段、结果入口和取消能力。完成通知不抢焦点、不改变当前阅读、不自动滚动。只有需要决定的事项进入“需要处理”，普通结果在用户下次查看时可发现。

E7 必须定义任务 ID、幂等键、事件序号、重连游标、取消与完成竞态、超时与失败重试、配额及 key 不可用时的终态。自动重试不能重复追加消息、生成多个成果或无限消耗额度。

现有浏览器 SSE 不被描述为后台持久执行。Worker、持久队列/执行平台、Fly.io 的责任在 ADR 中结合运行时限制决定，本文不预选新依赖。

## 7. 迁移、上线与回退

1. E1 仅新增带版本的本地视图快照；无效快照可清除而不影响正文、笔记与成果。
2. E2/E3 采用新增表/可选关联，保留原 artifact/anchor/document ID 与旧读取路径。
3. 旧成果先以兼容条目展示；需要包装成讨论时使用确定性映射，避免每次读取重复创建。不能把同一选区上的所有历史结果自动判断为同一问题。
4. 发布顺序为兼容的服务端读取/写入能力→新客户端→迁移验证；旧客户端不得因整包同步而删除新讨论、收藏或关联。
5. 回退关闭新入口或恢复旧视图，不做破坏性回滚删表；已经创建的新数据仍可读取或通过兼容视图访问。
6. 新讨论与成果写入跨对象时要求原子性或明确可重试流程；记录失败并提供恢复入口，不展示虚假保存成功。
7. 每个切片实际改变行为后，同次更新旅程契约和 `docs/project.md`；本文目标不能提前写成当前事实。

## 8. 验收矩阵

以下 RE 编号为目标场景，不替换现有 WJ 测试；实现对应切片时再加入可执行测试。

| ID | 场景 | 必须通过 |
| --- | --- | --- |
| RE-01 | A 原文中段与长解释→B→A | 两边位置、当前成果与布局恢复，不发新 AI 请求 |
| RE-02 | History 筛选→成果→原文→返回 | 原查询、条目、列表位置与焦点恢复 |
| RE-03 | 字体、栏宽变化后恢复 | 回到同一文本附近；用户滚动后不被延迟恢复拉回 |
| RE-04 | 刷新具体成果深链 | 登录与加载后打开正确用户对象；缺失/无权目标明确失败 |
| RE-05 | 第 8 段生成中选择第 12 段 | 原运行仍写入第 8 段问题，界面不误显示完成归属 |
| RE-06 | 三轮追问与显式加入第二引用 | 范围、消息顺序、引用和保存恢复一致 |
| RE-07 | 缺 key、EOF、stop/retry、断网 | 无虚假完成、保留部分结果和草稿、重试不污染其他问题 |
| RE-08 | 收藏→取消收藏→重开 | 内容仍在讨论记录中；用户笔记未被覆盖 |

| RE-10 | 390px、200% 缩放、中等宽度固定导航 | 无关键横向溢出；触控和键盘能完成求助、查看、返回 |
| RE-11 | 长回答生成时向上读 | 不强制滚动；新内容可发现；停止与重试可操作 |

修改前端时运行 `npm run lint`、`npx tsc --noEmit`、`npm test`、`npm run build`（`frontend/`）；Worker 修改运行 `npm run check`（`cloudflare/`）及相关测试；后端使用 uv、Ruff 及相关 pytest。仅文档改动检查链接、差异和事实一致性，不运行应用全套测试。

## 9. 用户验证与决策记录

先记录现有版本基线，再比较原文优先与精读优先原型。使用相同难度的真实阅读任务，交错测试顺序，记录是否因记住文本而影响结果。

| 指标 | 记录方式 | 用途 |
| --- | --- | --- |
| 首次有效帮助时间 | 从遇到问题到用户认为可以继续阅读 | 判断入口与回答呈现 |
| 返回定位成本 | 返回后额外滚动、搜索、点击及所用时间 | 判断现场与引用导航 |
| 讨论延续成功 | 用户无需重新描述原文即可完成三轮追问 | 判断问题模型与范围提示 |
| 隔天/一周找回成果 | 给出用户自己的回找任务，记录是否找到及耗时 | 判断 History 与收藏结构 |
| 理解与控制 | 用户能否说明回答依据哪段、哪些是自己写的 | 判断来源和成果边界 |
| 打断与任务发现 | 是否被无关完成状态打断，是否找得到需要处理事项 | 判断 agent 活动入口 |

首轮至少覆盖自主阅读和整篇精读两种任务；结合路线图 R1 招募读者。小样本用于发现问题，不宣称统计显著。原型应消除阻断级问题且不增加主要任务的回找成本，再扩大验证；阈值根据基线预先记录，不事后挑选有利指标。

待决事项在 E0/E2 的记录中填写：默认布局、短查询是否进入显式讨论、成果收藏默认视图、讨论标题策略、跨文档范围扩展方式。常驻任务运行平台、并发协议和删除语义在相关 ADR 中决策。
