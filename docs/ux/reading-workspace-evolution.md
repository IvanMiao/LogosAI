# 阅读工作台演进：待决设计

- 状态：目标设计；2026-09-18 收敛。E1 已实现，其余切片不是当前能力或实施授权。
- 实施顺序与启动条件由[路线图](../roadmap.md)维护；现行行为见[旅程契约](workspace-journey-contract.md)。
- 本文只保留跨切片边界与待决项；原型过程、研究摘录和单次验收不在此累积。

## 目标与保留边界

读者可以围绕原文持续追问，去另一篇核对引用，再返回继续阅读；隔天仍能找回问题、笔记和成果。

- 原文、讨论与成果有稳定身份，布局变化不复制内容；切换不改变已发送请求的范围。
- Explain、Translate、Vocab 保留一键入口；自动保存与用户主动收藏是不同动作。
- 保留现有 auth、BYOK、legacy analysis、history 导入及旧成果 ID。
- 当前浏览器 SSE 不提供关页后持续运行。常驻 agent 与持久任务分别验证，不预选平台或依赖。

## 切片与退出条件

| 切片 | 范围与依赖 | 退出条件 |
| --- | --- | --- |
| E0 布局原型 | 比较原文优先与默认双栏，复用当前工作区；观察前保持当前默认布局 | 桌面/窄屏完成求助、查找、返回；记录默认入口决策与依据 |
| E1 阅读现场与地址（已实现） | 文档/成果地址、按用户隔离的本地现场；行为由旅程契约维护 | N2 工程验收已完成；讨论价值仍需用户观察 |
| E2 问题讨论与追问 | 首版单篇 Discussion/Message；依赖可靠流终态与质量基线 | 三轮追问范围正确；切换选区不改变原问题；新数据可保存恢复 |
| E3 成果与历史组织 | 依赖 E2；笔记与收藏、讨论摘要、修订 | 旧成果可访问；取消收藏不删除内容；用户笔记不被 AI 覆盖；返回保留查询现场 |
| E4 引用预览与跨阅读 | 依赖 E1–E3；跨文档讨论有独立生命周期 | A→预览 B→打开 B→返回 A；权限、引用歧义和删除路径明确 |
| E5 辅助区与视觉收敛 | 可基于 E1 开展；最终布局结合 E0、E2/E3 | 同一讨论无副本；中等宽度、窄屏、键盘和 200% 缩放下可完成相同旅程 |
| E6 用户级 agent 与记忆 | 依赖已验证的单篇/跨篇讨论价值；先支持显式偏好和用户确认的信息 | 来源可查；记忆可修改/删除；删除后检索与缓存不再使用它 |
| E7 服务端持久任务 | 依赖 E6 与 Durable Jobs gate；平台通过 ADR 决定 | 关页后继续，重连不重复成果，完成/取消有唯一终态，并发不覆盖笔记 |

## 讨论、引用与成果

- 一次讨论围绕一个问题，可包含多个标明来源的引用；选区相同不代表问题相同。
- 新选区发起动作默认新建问题；“加入当前讨论”必须显式操作。打开旧成果不请求 AI，追问追加消息，重新生成产生修订。
- 问题标题先使用用户问题或确定性片段，允许重命名，不增加自动标题生成请求。
- 预览引用保留当前阅读现场；正式打开另一篇才导航。预览不递归堆叠浮层，关闭后恢复触发器焦点。
- 无权限、原文删除或引用定位不唯一时，显示保存的引用及原因，不猜测目标。
- History 逐步组织笔记与收藏、讨论记录；任务活动随 E7 引入。搜索明确本篇/全部阅读，首版只做本篇。
- 辅助区一次聚焦一种内容；展开/收回使用同一内容 ID。短查询、长讨论与窄屏入口由原型决定。
- 流式输出仅在用户跟随末尾时自动跟随；向上阅读后停止滚动并提示新内容。任务完成不抢焦点或切换文档。
- Session 导航保持平坦；固定阅读与固定侧栏分开。归档不同于删除；后台任务更新不改变最近打开顺序。

## 数据与迁移约束

| 对象/状态 | 归属与约束 |
| --- | --- |
| Discussion / Message | 问题、引用和已发送范围；E2 单篇，E4 再扩展跨篇；不塞进某篇文档的整包快照 |
| Artifact / 收藏 / 修订 | 保留现有成果身份；收藏是关系，不复制正文；消息与成果共享内容时只有一个正文所有者 |
| Run | 一次执行及其上下文、终态；运行成功与云保存成功分别表示 |
| URL / 本地现场 | URL 只存稳定目标，不含私人正文，也不代替权限检查；设备现场按用户隔离，复用 E1 |
| 云端内容 | 讨论、成果、收藏、任务；引入 agent 并发写入前确定版本前提、幂等与冲突恢复 |
| Memory | 偏好与用户确认的信息，带来源、范围和管理状态；删除记忆不隐式删除来源讨论 |

E2/E3 用新增表或可选关联渐进迁移。旧成果用稳定映射保留，不能把同选区的全部历史结果自动合成一个问题。
先发布兼容服务端，再发布客户端；旧客户端整包写入不能抹掉新关联。回退关闭入口，保留新数据可读，不删表。
跨对象写入需原子性或可重试恢复；保存失败保留草稿并明确提示，不能声称保存成功。
跨文档讨论、文档删除影响、条件写入及 API/schema 在相关切片启动时用 ADR 定稿。
E7 还需定义任务 ID、幂等键、事件序号、重连游标、取消竞态、超时、配额和 key 失效终态。

## 启动时需要回答

- E0/E5：默认布局、短查询入口、辅助区展开方式。用同难度任务比较首次有效帮助时间与返回定位成本。
- E2/E3：问题与修订边界、收藏默认视图。观察三轮追问、隔天找回成果及读者对来源/范围的理解。
- E4：跨文档范围扩展、路由、权限和删除语义；不提前承诺具体 URL/schema。
- E6/E7：记忆种类、可检查上下文和后台需求；“只依据本篇/不涉及后文”必须落实到输入与评估。

验证区分状态测试、组件旅程、真实浏览器、真实服务恢复和模型质量；mock 不证明后面三项。
实施后只更新受影响的主文档与测试，移除本文被现状取代的细节；执行记录放 PR，草稿与原始材料留本地。
